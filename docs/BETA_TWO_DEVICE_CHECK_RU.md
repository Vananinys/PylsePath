## Чек-лист на двух устройствах

Устройства A и B: владелец и уже назначенный ограниченный тестировщик соответственно. Реальные учётные данные вводят сами пользователи; пароли/токены/логи с координатами в отчёт не включать. Третий обычный аккаунт для проверки отказа необязателен — серверный отказ уже проверен, но UI-отказ можно проверить отдельным сеансом без изменения ролей.

### 1. Обновление без потери записи

1. Подключить A и B, разблокировать, разрешить ADB. Записать в локальный протокол модель, Android, номер приложения и назначение A/B. Не публиковать серийные номера.
2. Убедиться, что живые тренировки сохранены/завершены. Установкой не прерывать заезд.
3. Сверить versionCode каждого устройства. На 83 и выше не ставить 82; не использовать downgrade/uninstall/clear. При неоднозначном выборе телефона запросить соответствие A/B.
4. Проверить SHA256, пакет и сертификат выбранного APK. Для текущего сценария предпочтительна проверочная 83 на обоих аппаратах (если установленный код не больше); для чистой 82 использовать устройство с кодом ≤82. Фиксировать версии раздельно.
5. Устанавливать адресно `adb -s SERIAL install -r APK`. Проверить versionCode/versionName после установки, открыть приложение. Если устройство новее доступной сборки — оставить его версию, сравнение разных версий явно отметить.
6. Локальный 83: `audit/2026-10-30/screen-off-recording/pulsepath-83.apk`, SHA256 `86b5a76239dce4e2b0f15039ee0915e87727df8288c5a2af06eac88ecffd13ee`; перед использованием повторно проверить фактический файл и сертификат по метаданным рядом. Отсутствие этого локального APK на другом компьютере — отдельная зависимость, а не повод ставить 82 поверх 83.

### 2. Лаборатория и ограничения ролей

1. A: открыть Настройки, семь раз нажать именно заголовок; появляется «Для разработчика». Войти. Ожидание: лаборатория доступна, есть вход «Управление владельца», прежняя OwnerScreen открывается.
2. B: повторить семь нажатий. Ожидание: лаборатория доступна, **нет** входа управления владельцем; GPS/сеть/скорость — только демонстрация.
3. B: в «События и челленджи» доступно создание своего события. Проверить отсутствие назначения ролей, выдачи наград, ответов и завершения **чужих** событий. Просмотр ответов в собственном событии входит в права организатора; произвольный XP/награды — нет.
4. Не публиковать фиктивное событие ради UI-проверки: открыть форму и отменить. Серверные отказы уже проверены транзакционно. Если нужна настоящая публикация, обозначить событие как тестовое и завершить штатным действием после проверки.
5. Закрыть лабораторию/свернуть приложение во время симуляции, открыть снова. Не должно быть фоновой симуляции, новой тренировки в истории, XP, синтетической позиции у друга. Реальные административные экраны работают с настоящими данными — не нажимать выдачу наград/изменение ролей ради демонстрации.
6. При смене аккаунта снова открыть настройки/лабораторию; чужие права и незавершённая симуляция не должны переноситься. При отсутствии сети вход не должен предоставлять административные права без подтверждения сервера.

### 3. Синхронизация шлейфа A → B и B → A

1. С согласия каждого включить существующую передачу геопозиции друзьям и локальную видимость шлейфов. Зафиксировать исходные настройки, чтобы вернуть их после теста. Не расширять круг видимости.
2. На A: Внешний вид → Кастомизация → Мой шлейф; выбрать заметно отличимые эффект, цвет и размер, нажать «Сохранить». Дождаться исчезновения pending/подтверждения синхронизации. На B открыть карту друга.
3. Для появления геометрии получить минимум две свежие разные позиции. На улице пройти 20–30 м обычным шагом, дать GPS и сети получить обновления; стационарную симуляцию лаборатории не принимать за этот шаг. Задержку записи/получения и время появления записать, заранее гарантированное время доставки не обещать.
4. Ожидание на B: рисунок/цвет принадлежат A; аватар и конец хвоста движутся вместе; смена масштаба не переставляет отпечатки хаотично. Проверить направление при повороте карты. Старый путь до открытия карты не ожидается — хвост в памяти, не серверная история.
5. A выключает «Мой шлейф», сохраняет онлайн. После получения изменения на B хвост исчезает, аватар/геопозиция сохраняются при разрешённой трансляции. После включения скрытый старый хвост не возвращается: нужны новые позиции.
6. B меняет собственный эффект, сохраняет, проходит короткий участок. Проверить обратное направление на A. Локальное скрытие чужих шлейфов не должно перезаписывать выбор B.
7. На A временно отключить сеть, поменять эффект и сохранить. Ожидание: локальный pending, B не обязан увидеть несинхронизированное изменение. Вернуть сеть, дождаться повтора/подтверждения; проверить B. Не создавать новый аккаунт или сбрасывать данные ради повторной попытки.
8. При отключении передачи позиции новые реальные координаты не публикуются; старое положение/хвост может исчезать по правилам свежести. Не считать отсутствие новых точек ошибкой оформления.
9. Вернуть выбранные пользователями настройки, завершить/отменить тестовую тренировку штатно по их решению. Не сохранять симуляцию как настоящий заезд.

### 4. Протокол результата и условия остановки

Для каждого шага записать: A/B, версии обоих APK, действие, время/сеть/GPS, ожидаемый результат, наблюдаемый результат, источник подтверждения (пользователь, скриншот, ADB или сервер). Не смешивать их. Снимки с местоположением хранить только в локальном audit.

Если воспроизведён дефект: сохранить минимальную последовательность и безопасный диагностический лог **до** изменения кода; затем исправить конкретный модуль и повторить исходный сценарий и связанные проверки. Если аккаунты/устройства/ADB недоступны, отметить BLOCKED, не выдавать SQL-пробу или лабораторную симуляцию за физический проход.

**Текущая блокирующая зависимость:** два доступных телефона с A/B-сеансами и участием пользователей для ручного ввода (на прежнем телефоне ADB INJECT_EVENTS был запрещён). Сейчас нет ни одного ADB-устройства. Никаких новых разрешений/ролей для продолжения этой проверки не требуется.
