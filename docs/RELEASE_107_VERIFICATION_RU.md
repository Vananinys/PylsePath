## Исправление серверных прав

На действующем сервере подтверждён прямой grant TRUNCATE для authenticated
на `public.rides`, `public.live_positions`, `public.fcm_tokens`. Доступный
из приложения способ выполнить TRUNCATE не установлен. В клиентском коде и
телах функций public/app_private явных вызовов TRUNCATE не найдено.

Применена миграция `20261103184010_revoke_client_truncate_on_private_activity`:
отозван только TRUNCATE у PUBLIC/anon/authenticated. Проверены все три таблицы:
anon/authenticated — false, service_role — true. Сопоставление метаданных до/после
подтвердило неизменность SELECT/INSERT/UPDATE/DELETE и флагов RLS у этих ролей.
Данные не читались и не удалялись, проверочного TRUNCATE не было.
Повторная проверка: `tools/private_activity_privilege_checks.sql`.

Новый APK не нужен: изменение касается только серверных прав.
Остальные вопросы аудита (тела RPC геолокации, TTL позиций, полная цепочка
привилегированных RPC) этой проверкой не закрыты.
