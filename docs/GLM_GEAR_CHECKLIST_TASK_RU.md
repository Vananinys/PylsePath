## Модель и контракт

Сделай неизменяемую модель списка и пункта. Пункт содержит стабильный строковый ID, название и отметку checked. Список сохраняет порядок; наружу выдаётся неизменяемая коллекция. Операции возвращают новое состояние и не меняют переданные данные.

Поддержи добавление, переименование, переключение отметки, удаление и снятие всех отметок. Новый пункт получает ID от вызывающего кода: компонент может принимать фабрику ID для тестируемости, без новой UUID-зависимости. ID не должен зависеть от названия или индекса; редактирование сохраняет ID и checked.

Ограничения: максимум 30 пунктов; название после trim от 1 до 80 UTF-16 единиц, ID после trim от 1 до 80. Дубли названий запрещены после trim и toLowerCase; при переименовании исключай сам редактируемый пункт. Не обещай полную Unicode-нормализацию. Валидация модели и интерфейса должна совпадать, включая длинные emoji. Дубли ID запрещены. Неизвестный ID операции и недопустимый ввод дают явную ошибку, не удаляют и не заменяют данные молча.

Предусмотри строгое чтение и запись JSON-конверта версии 1. При чтении проверяй типы, границы, дубли, checked как bool и поддерживаемую версию. Некорректный элемент отклоняет весь документ. Не превращай повреждённый документ в пустой список. Чтение не должно менять входной Map/List. Укажи политику дополнительных полей; она должна быть последовательной и проверенной тестом.

## Интерфейс

Контролируемый виджет RideGearChecklist: принимает актуальную модель и onChanged. Изменения становятся видны после передачи нового значения родителем. Внутри хранится только временное состояние формы/диалога. Не сохраняй копию модели в initState, которая перестанет учитывать обновления родителя. Отдельный виджет не должен запускать тренировку или запрещать её начало.

Покажи название, прогресс «Собрано 2 из 5», список с чекбоксами, добавление и доступные действия редактирования/удаления. Пустое состояние объясняет, что можно добавить свои вещи. При лимите покажи понятное сообщение. Ошибки ввода выводи рядом с полем и сохраняй введённый текст. Не выбрасывай исключение модели из обработчика UI.

Удаление пункта и снятие всех отметок — через подтверждение. Отмена не вызывает onChanged. Для пустого или полностью неотмеченного списка сброс недоступен. Отметка каждого пункта — ровно одно изменение, без двойного переключения из-за вложенных onTap/onChanged.

Поддержи enabled=false: все изменения, в том числе из ранее открытого диалога, блокируются. При подтверждении диалога используй актуальную модель родителя: если список изменился снаружи, не затирай новые пункты старым снимком. Если редактируемый пункт исчез — покажи понятное сообщение и не создавай его заново.

Используй Theme.of(context), светлую и тёмную тему, подписи доступности и tooltip у иконок. На ширине 320 px и масштабе текста 1.6 не должно быть overflow. Длинный список прокручивается при ограниченной высоте, кнопки доступны. Не задавай обязательную фиксированную высоту на весь экран; опиши подходящие ограничения для встраивания в существующую подготовку. Текст не должен утверждать, что список гарантирует безопасность поездки.

Не добавляй шаблоны, рекомендации по здоровью, ежедневные напоминания и автоматический сброс после поездки: для них потребуется отдельное продуктовое решение.
