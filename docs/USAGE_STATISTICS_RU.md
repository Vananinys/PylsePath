# Статистика использования: текущий режим и развитие

## Что работает сейчас

Настройки → Помочь улучшить PulsePath. По умолчанию всё выключено. Отдельный текст и добровольное действие разрешают только локальные счётчики. Формат: день, версия приложения, событие из фиксированного enum и количество. Данные разделены между аккаунтами на устройстве. В экспорт не входят UID, e-mail, рекламный/установочный идентификатор, координаты, GPX, названия мест, сообщения, файлы или текст исключения.

Есть просмотр точного JSON перед ручной отправкой через системную программу, выключение и очистка счётчиков. Автоматического приёмника, сетевой очереди и SDK аналитики нет. Подключать пользовательские отчёты к прежнему зарубежному Supabase в этой задаче не стали. Историю записанных поездок задним числом в статистику не превращаем.

Хранятся последние 30 календарных дней; при открытии экрана/новой записи счётчики вне окна отбрасываются. Когда приложение закрыто, оно не выполняет фоновую очистку. На устройстве остаётся локальное подтверждение версии выбора. Отказ записи подтверждения не разрешает сбор через оптимистичный кеш.

Считаются открытия основных разделов меню, старты/ручные паузы/продолжения/сохранения/ошибки/отмены тренировок, построение/ошибки маршрута, ошибки потока GPS и попытки/успех восстановления. Это счётчики действий, не длительность посещения и не уникальные пользователи. Отсутствие события ещё не доказывает ненужность функции: выборка добровольная, альтернативные входы в раздел могут не считаться.

## Как смотреть результаты

1. Попросите каждого тестировщика по желанию прислать **один** отчёт за период, предварительно просмотрев его.
2. Сохраните JSON локально в `usage-reports/` (каталог исключён из Git). Не публикуйте исходные отчёты в issues.
3. Выполните `python tools/analyze_usage_reports.py usage-reports/tester1.json usage-reports/tester2.json`.
4. Откройте `analysis-output/usage.csv` в таблицах: сравнивайте события по версиям и число отчётов с каждым событием. Точные дубликаты файлов отбрасываются. Повторные накопительные отчёты одного человека могут пересекаться; без идентификаторов это не определяется.

Сначала смотрите ошибки сохранения, восстановления GPS и построения маршрута, затем частоту открытий разделов. Не считайте `workoutSaved/workoutStarted` точной конверсией: события не связаны ID сессии и могут пересекать границы периода. GPS stream error — техническая ошибка потока, а не все случаи плохого приёма спутников; нахождение в помещении само по себе этой метрикой не определяется.

## Что потребуется для автоматической отправки

Российского сервера пока нет (ответ владельца). До включения нового контура определить оператора и основания обработки, российское первичное размещение, договор с хостингом, регламент сроков/доступа/удаления, необходимые уведомления РКН и требования к возрасту/представительству. В приложении уже есть пользователи 14–17: не считать самовыбор возраста подтверждением полномочий.

Проверенная нормативная основа: https://mintrud.gov.ru/docs/laws/130 — статья 18(5) о размещении баз при сборе данных граждан РФ и статья 9 об отдельном согласии. Само согласие не устраняет требования локализации. Существующие аккаунты/треки всё ещё обрабатываются в зарубежном Supabase; добавление локальных счётчиков не делает весь прежний контур автоматически соответствующим закону.

Даже отчёт без UID нельзя безусловно считать анонимным: версия, дни и малое число тестировщиков могут раскрывать человека; выбранная программа пересылки может раскрыть отправителя. Полученные оператором файлы хранить с ограниченным доступом и сроком, не использовать для иных целей. Практический старт: удалить исходные добровольные отчёты после анализа (не позднее 30 дней), оставить необходимые сводные показатели; применимость и основания проверить для своего режима.

Будущий приёмник должен принимать только фиксированную схему счётчиков, отклонять произвольные свойства, не хранить содержимое запросов и IP в обычных логах, иметь ограничение размера/частоты, защиту доступа, HTTPS, срок очистки и проверку отзыва согласия. После появления адреса сервера нужна отдельная версия сетевого согласия: разрешение локальных счётчиков не разрешает скрытую будущую отправку.

Геоаналитику пока не добавлять. Для оценки качества карты достаточно агрегатов успешности маршрутизации/сбоев/восстановления, без точек начала/конца, домашнего района, конкретных тайлов и тепловых следов. Любой будущий сбор географии требует самостоятельного проектирования и отдельного выбора пользователя.
