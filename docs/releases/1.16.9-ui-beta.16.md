# UI Beta 1.16.9-ui-beta.16+124

Завершён этап согласованного доступа к локальному Signal-хранилищу из двух работающих изолятов.

## Исправления

Два открытия больше не делят один закрываемый SQLite-handle (singleInstance=false). Между изолятами работает очередь на путь базы, охватывающая открытие, транзакцию, enrollment, чтение статуса и закрытие. Это устраняет SQLITE_BUSY при одновременной работе с однопоточным Android-драйвером. Close идемпотентен; использование закрываемого handle завершается отказом, незавершённая запись откатывается. Состояние ratchet и зашифрованные inbox/outbox по-прежнему фиксируются вместе до выдачи результата.

## Фактическая проверка

До исправления регрессионный тест воспроизвёл database_closed после закрытия соседнего handle. В Android QA отдельные соединения без очереди воспроизвели SQLITE_BUSY на PRAGMA journal_mode. После исправления оба Android-теста прошли на эмуляторе API 37 x86_64: параллельная отправка 8+8 Signal-пакетов с успешной расшифровкой всех 16 в обратном порядке и 25+25 обновлений с итогом ровно 50. Проверка на физическом телефоне не выполнялась: ADB не видел подключённых телефонов. Источник QA сохранён в tools/signal_android_qa/.

## Ограничения

Это проверка двух работающих Dart-изолятов одного процесса через настоящий Android SQLite/Keystore, а не доставка FCM с сервера и не два отдельных FlutterEngine. Если владелец блокировки погибает, очередь не отбирает живую блокировку по таймеру: возможен отказ до перезапуска процесса. Нельзя объявлять проверенными убийство процесса, прерывание владельца транзакции и очистку контекста аккаунта между headless engine.

Реальные чаты сохраняют схему beta14; Signal остаётся отдельным локальным экспериментом E2EE_SIGNAL_TEST. Переход переписки, серверные device/prekey RPC, восстановление архива и связывание устройств ещё не включены. Обычные пользовательские данные, сообщения и ключи не очищаются.
