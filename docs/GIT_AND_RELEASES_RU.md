# Git, резервные снимки и выпуск обновлений

GitHub: https://github.com/Vananinys/PylsePath. Репозиторий публичный.

## Сохранить работу

В PowerShell из проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\checkpoint.ps1 -Message "Описание сделанной функции" -Push
```

Скрипт сохраняет исходники, тесты и документацию, проверяет индекс на распространённые секреты и отправляет текущую ветку. Не добавляет APK, ключ подписи, локальные отчёты и audit. Это проверка по шаблонам, а не гарантия обнаружения любого секрета: просматривайте staged diff перед публичной отправкой.

`main` — проверенные изменения; новые задачи — отдельные `codex/...` ветки. GitHub Actions проверяет каналы, согласие и целостность данных без ключей подписи. Ограничения защиты main зависят от настроек GitHub; обязательные проверки не следует считать включёнными без отдельной проверки.

Контрольная метка `checkpoint-1.12.15-local` содержит снимок исходников до каналов, включая уже имевшиеся изменения виджета шагов. Локальная и прежняя GitHub-истории соединены merge-коммитом. Старый README GitHub сохранён в docs/git-history/GITHUB_INITIAL_README.md.

## Восстановить код без потери текущей работы

```powershell
git fetch --tags origin
git log --oneline --decorate -15
git worktree add ..\pulsepath-recovered checkpoint-1.12.15-local
```

Будет отдельная папка со снимком. Текущий рабочий каталог сохраняется. Не используйте `reset --hard`, `clean` или зеркальное копирование для восстановления. Для отмены отдельного коммита готовьте `git revert` в отдельной ветке и проверяйте результат: изменения данных и сервера требуют самостоятельного плана совместимости.

Ключ подписи и android/key.properties сохранены отдельно в защищённой папке `%USERPROFILE%\PulsePathBackups`. Там есть git bundle контрольного снимка. Эти файлы нельзя загружать в публичный GitHub. Для защиты от поломки самого диска нужна дополнительная шифрованная копия на другом носителе: локальный каталог её не заменяет.

## Стабильный и бета-канал

Настройки → Версии и бета-тестирование. По умолчанию стабильный канал. Участие в бета-тесте подтверждается отдельно, счётчики оно не включает.

- Стабильные метаданные — `public.app_releases`; бета — отдельная `public.app_beta_releases`. Старые клиенты читают только стабильную таблицу.
- Бета в GitHub Releases публикуется как prerelease с именем `1.12.17-beta.1` и соответствующей меткой `v1.12.17-beta.1`.
- **versionCode всегда растёт между обоими каналами**. При продвижении бета в стабильный канал создаётся новая сборка с новым кодом. Не перезаписывайте опубликованный APK.
- Для каждого нового выпуска фиксируйте точный git commit в `source_commit`, Git-теге и GitHub release target. Исторические метки, созданные до подключения исходников, не доказывают соответствие старому APK. Их не перемещали и не переписывали.
- Сертификат APK должен совпадать с действующим. После загрузки проверьте SHA256 и размер опубликованного объекта, затем публикуйте метаданные. Бета-таблица не запускает массовый push стабильного канала.
- Можно скачивать архивные APK. Android запрещает обычную установку меньшего versionCode поверх большего: https://developer.android.com/studio/publish/versioning.
- Для возврата с неудачной беты берите прежний Git-снимок, проверяйте совместимость локальных данных/сервера и выпускайте исправление с новым, большим versionCode. Не предлагайте пользователю удалить приложение: несинхронизированные поездки могут потеряться.

Схема добавления каталога: docs/releases/channels_schema.sql. RLS разрешает клиентам только чтение опубликованных строк; писать из приложения нельзя.
