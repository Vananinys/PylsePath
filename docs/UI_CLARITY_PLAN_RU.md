# Полная ревизия понятности интерфейса PulsePath

Дата: 31.10.2026. Основание: запрос пользователя разобрать весь интерфейс и улучшить его понятность, предварительно описав этапы.

## Исходное состояние и границы

При подготовке плана: ветка `codex/trails-upgrade-safety`, HEAD `21a89da`, версия исходников `1.12.28-beta.2+83`, рабочее дерево чистое. Найдено 48 Dart-файлов в `lib/screens`; это число файлов, а не число проверенных экранов. Главная карта, панели, диалоги, меню и вложенные редакторы требуют отдельного учёта.

Прочитаны сводка проекта, последние записи журнала, структура и прежний `INTERFACE_REVIEW_BACKLOG_RU.md`. Просмотрены входы карты и исходники настроек/кастомизации в объёме подготовки плана. Полный аудит поведения и визуальный обход пока не выполнены. Старый список проблем не считается доказательством текущего дефекта.

Код, файлы, настройки, сохранённые поездки и пользовательские данные без разрешения не удалять. Изменения оформления сохраняют доступ к существующим функциям; перенос точки входа фиксировать в карте переходов. Права, публикация координат, сохранение и синхронизация не расширяются ради упрощения UI.

## 1. Полный реестр поверхностей и переходов

- Обойти `lib/screens`, `lib/main.dart`, `lib/src/map_screen`, `lib/widgets`; найти дополнительные UI вне этих каталогов через Scaffold, диалоги, меню, bottom sheets и маршруты навигации.
- Файл `UI_AUDIT_INVENTORY.csv` — начальный файловый индекс кандидатов, не готовая карта экранов. Для каждого кандидата определить, является ли он самостоятельным экраном, состоянием, вложенным редактором или общим компонентом.
- Дополнить реестр конкретными поверхностями: вход, выход/Назад, основная задача, нужные права, состояния и связанные компоненты. Отдельно учитывать обычного пользователя, организатора, модератора, владельца и тестировщика.
- Зафиксировать исходные снимки доступных экранов. Для недоступных сценариев записать зависимость, не отмечать их проверенными.

Результат: карта всех доступных путей и список поверхностей без неопознанных точек входа. Новые найденные поверхности добавляются до завершения аудита.

## 2. Сквозные задачи пользователя

Пройти реальные цепочки, а не только отдельные красивые экраны:

1. Первый запуск → регистрация/вход/восстановление → разрешения → карта.
2. Выбор активности → запись без маршрута → пауза/продолжение → завершение → сохранение → история.
3. Поиск/создание/импорт маршрута → изменение точек/остановок → сохранение → навигация → завершение.
4. Офлайн-подготовка → отсутствие сети → доступные действия → восстановление сети.
5. Группа → приглашение → сбор → готовность → совместный старт → личная запись → выход/финиш.
6. История → детали → аналитика/сравнение → медиа → публикация/экспорт с понятной приватностью.
7. Друзья → публичный профиль → чат → вложение/ответ/повторная отправка.
8. Активность/шаги → тренировочный центр/календарь → цели/достижения → результат.
9. Гараж → транспорт → обслуживание и редакторы.
10. События → условия → участие/опрос → прогресс → получение награды.
11. Профиль/оформление → личный шлейф → настройки карты/голоса/фона/приватности → обновления/резервная копия.
12. Специальные роли → управление событиями/модерация/лаборатория; обычному пользователю эти возможности не приписывать.

Результат: для каждой цепочки записаны непонятный шаг, причина, последствие и предлагаемая правка.

## 3. Карточка проблемы и приоритет

Для каждого замечания: поверхность и путь входа → фактическое наблюдение → почему пользователь затрудняется → изменение → критерий проверки → статус кода → статус визуальной/физической проверки.

- P0: риск потерять запись/данные, случайно завершить действие или открыть приватные материалы.
- P1: непонятен следующий шаг, режим, результат сохранения или способ исправить ошибку.
- P2: перегрузка, трудночитаемые показатели, неодинаковые названия и навигация.
- P3: декоративные расхождения, которые не мешают задаче.

Проблемы из старого backlog сначала воспроизвести. Не называть предположение подтверждённым дефектом.

## 4. Общие правила интерфейса

- Согласовать словарь: маршрут (план пути), запись тренировки, навигация, группа, личный шлейф и записанный след. Одно действие называется одинаково во всех точках входа.
- Определить иерархию основных/вторичных/опасных действий. На каждом состоянии есть заметный следующий шаг; нужные команды во время записи доступны сразу.
- Сначала показывать главное, дополнительные параметры раскрывать по задаче. Длинные инструкции разбивать на короткое объяснение рядом с конкретным действием.
- Использовать существующую тему и компоненты: единые заголовки, типографика, интервалы, карточки, поля, переключатели, кнопки и сообщения.
- Подписи объясняют результат действия. Иконки без текста имеют понятные tooltip и семантические имена; состояние не передаётся только цветом.

Результат: короткий словарь и набор общих правил, затем применение к конкретным замечаниям.

## 5. Карта, запись и навигация — первый блок реализации

- Отличить просмотр карты, подготовку, запись, ручную/автопаузу и навигацию. Определить главное действие для каждого режима.
- Проверить GPS, точность/давность координат, отсутствие сети, возврат к позиции, поиск, панели друзей и городские отметки.
- Проверить читаемость показателей, единицы, голос, интервалы, круги, медиа, сворачивание панелей и доступность команды завершения.
- Разделить остановку навигации, выход из группы и завершение личной записи; проверить подтверждения и возврат после отмены.
- Не менять поведение фоновой записи только ради оформления. Сохранять возможность увидеть реальное состояние тренировки после возвращения в приложение.

## 6. Маршруты, места и офлайн

Проверить создание, сохранённые маршруты, точки/остановки, импорт/экспорт, места поблизости, сохранённые места, детали маршрута, карты и голосовые параметры. Раздельно показывать сохранённую геометрию, наличие тайлов и возможность сетевого пересчёта. Объяснить недоступное действие и способ продолжить; сбой поиска не превращать в «ничего не найдено».

## 7. Остальные пользовательские разделы

Последовательно: история/итог/медиа/аналитика/теплокарты → шаги/тренировки/достижения → группы/друзья/чаты/лента → события → гараж и вложенные мастерские → профиль/кастомизация/настройки → вход/приватность/резервная копия/обновления/о приложении → служебные роли и лаборатория.

Каждый блок получает те же проверки действий, текста, навигации и состояний. Предыдущий редизайн группы или настроек не освобождает их от нового обхода.

## 8. Состояния и доступность каждого блока

- Первое открытие, загрузка, пусто, успех, ошибка, повтор, отсутствие сети и восстановление; устаревшие или частично загруженные данные.
- Разрешение ещё не запрошено, отказано, запрещено системно; объяснение причины и доступный следующий шаг.
- Длинные имена/сообщения, клавиатура, системные отступы, прокрутка, экран шириной 320 логических пикселей, крупный системный текст до 200%, обе темы и альбомная ориентация там, где поддержана.
- Контраст текста/элементов, области касания ориентиром 48×48 логических пикселей, TalkBack, порядок фокуса, понятные имена кнопок, отсутствие зависимости только от цвета/жеста.
- Системный Назад, повторное открытие, сворачивание/возврат, сохранение введённых значений и отсутствие повторной отправки по двойному нажатию.

Неприменимые проверки отмечать с причиной; непроверенные не выдавать за пройденные.

## 9. Проверка изменений и устройство

После каждого блока — просмотр diff и целевые проверки изменённого поведения; общие компоненты дополнительно проверить на потребителях. Финальный проход — сквозные сценарии, снимки до/после и сборка. Содержательные проверки выбираются по риску, а не ради количества тестов.

После изменений приложения проверить подключённые устройства. Если телефон доступен, установить совместимое обновление без удаления приложения/очистки данных/понижения версии; при неоднозначной цели уточнить устройство. Установка не прерывает живую запись без выяснения её состояния. Если устройство отсутствует или управление недоступно, записать ограничение. Сборка, установка, визуальная проверка и результат реальной тренировки — отдельные факты.

## 10. Завершение и выпуск

Аудит завершён, когда все найденные поверхности классифицированы, все применимые состояния пройдены либо имеют явную зависимость, подтверждённые проблемы обработаны, а оставшиеся ограничения перечислены поимённо. Улучшение интерфейса завершено, когда изменения проверены, основные цепочки проходят без потери действий и данных, а пользователь может понять: где он, что происходит, что делать дальше и как вернуться.

Обновить журнал и сводку; приложить список изменений по блокам и отдельный список оставшихся физических проверок. При выпуске выполнить `GIT_AND_RELEASES_RU.md`: канал по фактическому объёму, новый versionCode, проверенный APK/подпись, GitHub Release, каталог приложения и проверка серверной отправки уведомления. Старые опубликованные APK не перезаписывать.
