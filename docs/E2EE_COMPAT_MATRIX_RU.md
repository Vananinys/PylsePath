## Подтверждённые дефекты

**D1 (исправлен, ветка codex/stable-locked-hint)** — chat_service.dart:381-384:
42501/E2EE_UPGRADE_REQUIRED в stable-сборке показывался как «Не удалось
отправить сообщение. Проверьте интернет.» — пользовательstable-клиента
получал неверную причину отказа. Исправление: маппинг в
«Чат переведён в защищённый режим. Обновите приложение до UI Beta…»
(chat_service.dart:384-392) + тест test/locked_conversation_error_test.dart
(мок PostgREST 403/42501; важная деталь — мок обязан передавать
`request:` в http.Response, иначе postgrest_builder.dart:474 падает на
`response.request!`). Проверки: locked_conversation_error +
chat_e2ee_transport + notification_config → 6 passed, 3 skipped (live-гейт).

**D2 (info, не исправлялось)** — отсутствует автоповтор недоставленных чат-
сообщений при восстановлении сети; повтор только ручной. Потери нет (pending
в защищённом кэше), дублей нет (детерминированный messageId). Осознанный
компромисс; для стабильного релиза можно оставить как есть.

**D3 (info)** — «отсутствие переподписки Realtime» из общего аудита смягчено:
авто-rejoin есть на уровне SDK; остаточный риск — только состояния
`channelError` при живом сокете (полностью не верифицировано) и задержка
доставки до следующего rejoin/открытия чата.

**D4 (не проверяемо из репо)** — серверная DELETE-политика encrypted-строк
(e2ee-guard не охватывает DELETE, e2ee_chat_schema.sql:99-100). Требует
выгрузки политик с прод-БД.

## Ограничения

- Все строки матрицы — статический анализ; поведение двух реальных устройств,
  FCM и живого Realtime не проверялось (запрещено заданием).
- Локальные тесты покрывают маппинг ошибки, транспорт и конфигурацию
  уведомлений; WebSocket-реjoin SDK и фоновые изоляты тестами не покрыты.
- beta12/beta13 различаются только push-превью (см. задачу 2); в этой задаче
  не повторялось.

## Рекомендации перед стабильным релизом

1. Объединить фиксы веток codex/stable-locked-hint и codex/push-reply-no-echo
   (обе — минимальные клиентские правки с тестами).
2. Решение по превью в уведомлениях (настройка, дефолт-заглушка) — задача 2.
3. Серверная миграция сериализации пары — задача 1 (не применять без
   изолированной проверки).
4. Перед релизом: выгрузить с прод-БД политики chat_messages (включая DELETE)
   и бакета chat_media — единственные невидимые из репо элементы матрицы.
5. Живой двухустройственный прогон (восстановление ключа, офлайн-повтор,
   смена аккаунта) — по чек-листу docs/E2EE_IMPLEMENTATION_RU.md (п.10).
