# Навигационный выпуск 1.12.25

## Что реализовано

- Подготовка области всего маршрута, а не только окружности финиша. Консервативный прямоугольник с запасом, масштабы 13–16, не более 8000 тайлов. Слишком большие, некорректные и пересекающие линию смены дат маршруты отклоняются до скачивания. Это область, а не оптимизированный узкий коридор.
- Проверка каждого ожидаемого URL тайла непосредственно в текущем FMTC-кэше без HTTP. Статус — число найденных тайлов на момент проверки, не вечная гарантия сохранности и не дорожный граф. После возвращения с экрана карт проверка повторяется; доступна ручная перепроверка.
- По явному ответу пользователя источник для массовой загрузки не подключается. При пустом OFFLINE_TILE_URL предзагрузка отключена. Нельзя выдавать текущий выпуск за комплект карт всей страны. Сохранение геометрии/инструкций и проверка просмотренного кэша доступны без нового поставщика.
- На Android существующий канал состояния сети переключает главную карту на чтение кэша при потере соединения. Без настроенного источника сохраняется текущий слой с его просмотренными тайлами; при выборе «Только офлайн» используется источник проверяемой карты. Подготовленный слой масштабирует тайлы 16-го уровня при дальнейшем приближении, вместо запроса отсутствующего 17-го. Текущий слой корректно атрибутируется.
- Голос Android: отдельная относительная громкость 0–100%, обычные или более редкие подсказки поворотов. Значение передаётся нативному TextToSpeech через KEY_PARAM_VOLUME и ограничивается диапазоном. Русский голос должен быть установлен на телефоне до поездки; общая громкость мультимедиа также влияет на результат.
- Ручное онлайн-подключение впереди: при отклонении кнопка alt_route выбирает близкую точку в диапазоне 50–1500 м впереди по исходному прогрессу (не дальше 3 км от текущей позиции), строит дорожное подключение и сохраняет оставшийся трек и конечную точку. Проверяется точность конца соединения (до 10 м). Сохраняются инструкции соединения и оставшегося трека; при отсутствии инструкций есть геометрическая подсказка. Исходный маршрут в библиотеке и записываемая тренировка не перезаписываются.
- Подключение не выполняется автоматически на треках с разрывами/обязательными остановками: здесь нужен ручной выбор. При ошибке сети/неподтверждённом соединении старый путь остаётся. Выбранная впереди точка не гарантирует отсутствие разворота по фактическим дорогам — их ограничения определяет сервис маршрутизации.
- Места по пути: вода, кафе/рестораны, велосипедный магазин/ремонт, скамьи/укрытия/пикник через существующий Overpass. Поиск только по кнопке, один запрос одновременно; UI сообщает, что геометрия отправляется источнику. Обрабатываются nodes/центры ways, исключаются private/no, явно непитьевая вода, недопустимые координаты и дубликаты. Отображаются расстояние вдоль трека и расстояние от линии по прямой; это не подтверждённая дорога к POI.
- Можно сохранить точку локально через существующий SavedPlacesRepository; для редактируемого построенного маршрута — добавить промежуточную остановку и пересчитать. Для активной навигации/сохранённого трека изменение пути сперва нужно выбрать отдельно. Авторизация проверяется до действий и после ответа маршрутизатора.
- POI ограничены 2000 точками входного пути, 500 результатами и таймаутом. Ошибки/частичные ответы не превращаются в сообщение «мест нет». Полнота OSM, наличие воды и режим работы не гарантируются.
- В предстартовом интерфейсе прямо указано: нулевые поля высот не доказывают плоский маршрут, а предпочтения по тишине/подъёмам/остановкам текущий сервер не применяет. Фиктивные кнопки и обещания безопасности не добавлены.

## Что проверено и что не подтверждено

- 37 целевых проверок пройдены в tests-verified.log; после окончательных изменений запускается tests-release.log. Покрыты планы тайлов/лимит/географические края, переходы сети, повторная синхронизация и стабильный ID, ошибки восстановления геопозиции, черновики, сохранённая навигация, POI-парсинг/ошибки источника, громкость/редкие подсказки, откат подключения впереди и сохранение конечной точки.
- Схема production rides проверена: уникальный rides_pkey по id. RidesService использует upsert с устойчивым rideId; тесты повторов проверяют повторную отправку с тем же ID. Это не доказательство отсутствия любого возможного сбоя облака, но отдельную новую очередь/схему не вводили.
- Живые проверки Overpass: один запрос получил HTTP 406, следующий завершился таймаутом без ответа. Следовательно, доступность и качество данных для городов не подтверждены. В приложении это видимая ошибка источника, не пустой успешный результат. Платный/неизвестный запасной сервис не подключался.
- Авиарежим, процесс-kill и расход батареи на реальном телефоне не проверены: ADB не обнаруживает устройства. Модульные тесты не заменяют эти измерения. Озвучивание физически не прослушано.

## Остаточные зависимости и дальнейшие направления

| Направление | Польза | Сложность/зависимость | Решение сейчас |
|---|---|---|---|
| Массовая офлайн-загрузка | Высокая | Разрешённый источник и условия использования | Пользователь явно выбрал выпуск без подключения источника |
| Автономный расчёт по дорогам | Высокая | Локальный дорожный граф, SDK/данные, размер и обновления | Не реализован; UI честно требует сеть для пересчёта |
| Тише / меньше подъёмов / меньше остановок | Высокая | Поддерживающий веса граф, достоверные высоты/светофоры и сравнение альтернатив | Нынешний HTTP OSRM не предоставляет этих весов в клиентском запросе; без нового обоснованного backend не обещаем |
| Смысловой поиск | Средняя после надёжной основы | Сначала фильтры и поиск мест, затем оценка спроса; ИИ не нужен для базовых задач | Новые ИИ/платные API не добавлялись |
| Анализ поездок | Высокая, большая часть основы уже есть | WorkoutDetails/история/круги/сравнение; высоты и остановки требуют проверки качества GPS | Существующие функции сохранены; дальнейшие выводы после контроля данных |
| Часы и велокомпьютеры | Зависит от аудитории | GPX уже есть; прямой обмен потребует конкретного устройства, SDK/прав и измерения батареи | Новых интеграций без устройства и оценки не вводили |
| Близкие / live tracking | Высокая | Уже есть друзья и группа; доверенные лица/срок доступа требуют отдельного UX | Доступ к позиции не расширяли, экстренную надёжность не обещаем |
| Препятствия и перекрытия | Средняя–высокая | Существующие городские отметки, TTL/подтверждение/модерация; изменение графа только по проверенным данным | Автоматическое исключение дорог по непроверенным сообщениям не добавлено |

Стоимость новых платных сервисов в этом выпуске — отсутствует: они не подключались. Существуют лишь сетевые обращения к уже используемым источникам и локальная обработка. Архитектурные изменения ограничены дополнительным callback существующего NetworkRecoverySync, виджетами подготовки и отдельным сервисом поиска POI; новой серверной инфраструктуры и SDK нет.
