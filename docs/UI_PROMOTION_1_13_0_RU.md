# PulsePath1.13.0 — перенос интерфейса UI Beta

Разрешение пользователя01.11.2026: текущий набор UI Beta переносится целиком, будущие функции — по одной за стабильный выпуск.

Основа: stable1.12.30+94 (b918078) и UI Beta10+95 (5027ca7). Контрольная точка61c4995, отдельный worktree C:/src/pulsepath-ui-promotion, ветка codex/ui-beta-promotion. Старые исходники/реализации сохранены, файлы не удалялись.

Перенос: светлая/тёмная/системная тема и читаемые меню; события, сохранённые места/маршруты; клубы и реальные чаты/события/уведомления; заезд с приглашением, добровольным принятием, обычной подготовкой и ручным стартом; указатели только принятому составу заезда; собственный и публичный профили; все14 дополнительные конфигурации карты через тот же основной FlutterMap. Сохранены актуальные географические шлейфы/Пульс и рабочая авторизованная лаборатория с изоляцией её записей.

UI_BETA остаётся флагом идентичности com.pulsepath.app, своего каталога и topic. AppVariant.modernInterface включает уже одобренные функции и в обычном com.example.pulsepath; сборка stable не требует UI_BETA=true. Будущую экспериментальную функцию подключать отдельным флагом, не расширяя общий набор автоматически. UI Beta95 остаётся отдельным установленным приложением/каталогом, локальные данные между пакетами не переносятся.

Серверные клубные RPC/схемы уже существовали; DDL/изменений прав/пользовательских данных не выполняли. Новый stable регистрирует поддержку клубного push прежним защищённым RPC. send-club-push v3 отличается от проверенной v2 только общей подписью «Откройте PulsePath, чтобы посмотреть» вместо UI Beta; опубликованный код сверен, запрос без webhook-секрета даёт401.13 изолированных worker-сценариев прошли без внешней отправки сообщений.

Первый полный прогон обнаружил16 несоответствий старых тестовых переходов новым экранам. Сохранены смысл и проверки: расчёт/сохранение целей и повреждённая история, вход в историю, расширенная координация/передача управления, запрос подготовки без старта, точка/причина остановки, конструктор/undo, фильтры тепловой карты и избранное. Для тестов карты монтируется настоящий PrimaryMapPortal вместо ожидания вторичной карты. Дополнительно исправлен реальный недостаток: ListTile заголовка задачи при крупном шрифте перекрывал свободную карту. Заголовок стал двумя рядами, позиция zoom-кнопок учитывает его измеренную высоту. Следующие итоги проверки/сборки/выпуска фиксируются после завершения.

Физический сценарий двух аккаунтов, длительный заезд, голос/батарея и просмотр финального экрана на телефоне не подтверждены. Эти ограничения не заменяются программными тестами. Установка только при доступном телефоне, без удаления/очистки/понижения.
