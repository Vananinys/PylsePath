# Разбор результатов DeepSeek: совместимость обновлений

Основа — текущий источник 1.12.18+71, commit 16f2ed4; отдельная QA-копия DeepSeek не изменялась. В папке «для дипсика» найдены старые отчёты медиа/записи, прежняя integrity-копия и новый REPORT_RU.md с восемью файлами тестов upgrade_qa. Новых самостоятельных дополнений к этому отчёту не найдено.

## Исправления D1–D6

1. История резервирует полный исходный JSON при потере неизвестных полей строки и конверта, а также нормализуемых значений. Охвачены primary и recovery. Миграция известных дат/индексов старых форматов не считается сама по себе повреждением.
2. Библиотека маршрутов не перезаписывается при обычном чтении. Запись на чтении остаётся только при присвоении недостающих стабильных ID. Перед потерей неизвестных полей сохраняется оригинал. Нечитаемые данные резервируются, запись блокируется.
3. Повреждённая очередь чата сохраняется verbatim и не подменяется новой очередью. Для продолжения общения новые сообщения пишутся в отдельный recovery-архив. В интерфейсе показывается уведомление. Если резервирование не удалось, запись не разрешается; если повреждён и recovery, его оригинал тоже резервируется и запись блокируется.
4. Сохранение сообщений и черновика старым экземпляром после смены аккаунта завершается StateError. Проверка владельца повторяется после асинхронного получения prefs. Данные следующего аккаунта не затрагиваются. Фоновые записи из UI обрабатывают ошибки жизненного цикла.
5. Неверный тип одного AppSettings-поля не отменяет чтение других полей. По аналогии исправлено безопасное чтение настроек навигации, чтобы неправильный тип настройки оформления не препятствовал запуску.
6. Ошибка или false от записи канала приводят к перечитыванию кеша. Если и чтение платформы не удалось, бета не считается подтверждённой до успешного перечитывания.

## Что уточнено относительно отчёта

- Сначала все шесть красных сценариев воспроизведены на неизменном проверяемом Dart-коде. Это условные воспроизведения на fake-платформе, а не свидетельство уже потерянных реальных поездок пользователей.
- Часть исходных проверок backup читала оптимистичный кеш и искала только подстроку. Они усилены: читается platform.getAll и проверяется полная исходная строка.
- В исходном тексте было сказано, что ChatScreen._restoreLocal уже обрабатывает ошибку чтения. Это не соответствовало коду. Обработка добавлена отдельно; серверная история продолжает загружаться, предупреждение находится в теле чата.
- Дополнительно закрыт упомянутый latent-путь SavedRoutesRepository.save/clear на свежем экземпляре: они читают/проверяют прежний архив, прежде чем писать. Явный clear нечитаемого архива не затирает неизвестные данные.
- Отдельные гипотезы о неизвестных полях SavedPlaces/RideMedia/WorkoutDraft и структуре progress.days не объявляются исправленными этим патчем. Нужны отдельные воспроизведения. Публичный API/сетевой загрузчик APK не проверялся реальной сетью в модульных тестах.

Восстановление отдельных сообщений из обрезанного JSON не выдумывается: сохранены точные исходные байты для последующего восстановления. Новые сообщения доступны из дополнительного архива. Двойное повреждение не выдаётся за полностью восстановленный диалог.

При downgrade на старые опубликованные APK исправления нового читателя не появляются в их коде. Для безопасного возврата нужен совместимый новый выпуск прежнего кода с большим versionCode.
