# Раунд 2: криптографические инварианты и жизненный цикл ключей E2EE

Дата: 10.11.2026. Read-only аудит ветки codex/chat-e2ee (HEAD d838929).
Только статический анализ и локальные unit-тесты (без аккаунтов, ключей и
сети); RLS/SQL-триггеры, push и уведомления не анализировались. Протокол,
формат сообщений и recovery-семантика не менялись; тесты — на ветке
codex/e2ee-invariant-tests.

## Генерация и хранение (подтверждено по коду)

- Identity: seed 32 байта из sodium randombytes (e2ee_identity_service.dart:
  104-108) → детерминированная пара X25519 через box.seedKeyPair (:71-78).
  Recovery-ключ: 32 байта CSPRNG пакета cryptography (e2ee_recovery_vault.dart:
  11-12) → base64Url, показывается только по запросу.
- Хранение: только FlutterSecureStorage с owner-скопированным ключом, проверка
  владельца до/после каждого await и подтверждение записи повторным чтением
  (e2ee_secret_store.dart:29-63); plaintext-fallback в SharedPreferences
  отсутствует; кэш/черновики беты — защищённое хранилище (chat_local_store.dart:
  20, 115-136).
- Импорт/экспорт: экспорт — exportRecoveryKey из защищённого хранилища
  (e2ee_identity_service.dart:148-149); импорт — restore() с проверкой
  соответствия опубликованному ключу (:167-172), запретом замены действующего
  ключа (:173-188) и сохранением пинов (:193). Экран: FLAG_SECURE (:23, :90),
  поле ввода obscure/без обучения IME (e2ee_keys_screen.dart:144-149),
  generic-ошибки без эхо введённого ключа (:75-80).

## Проверенные сценарии

**Подтверждено (свойства):**

1. **Nonce**: случайный 24 байта на каждый пакет каждого сообщения
   (e2ee_box_codec.dart:45-56). Тест: 1000 пакетов одной пары — все nonce
   уникальны (e2ee_box_invariants_test.dart); коллизионный бюджет 2^192 —
   reuse при объёмах до триллионов сообщений на пару даёт вероятность <2^-110.
   Статистическая проверка CSPRNG, не полное доказательство.
2. **Привязка**: v/id/sender/conversation внутри аутентифицированного plaintext
   (box_codec:31-38), проверка при расшифровке (:90-95); отправитель и
   получатель — через MAC пары (publicKey, secretKey) (:82-87).
3. **Подмена/повтор**: tamper ciphertext — MAC fail (существующий
   e2ee_box_codec_test.dart:59-61); tamper nonce — MAC fail (новый тест);
   перенос пакета между слотами получателей в одном конверте — MAC fail
   (новый тест); переиспользование конверта под другим id/диалогом — context
   mismatch (существующий тест :50-54); чужой ключ — MAC fail (:48-49).
4. **Размеры/форматы**: публичный ключ 32 байта после декодирования
   (e2ee_identity_service.dart:217-218), сервер-регексп 44 символа
   (e2ee_identity_schema.sql:33); recovery-контейнер: формат, ровно 4 ключа,
   nonce 12, mac 16, лимит 8 МБ до парсинга (vault:53-68); битые base64 и
   короткие пакеты — исключение, не краш (новый тест).
5. **Downgrade**: клиент проверяет v на конверте и внутри plaintext (:74, :90);
   v='pulsepath-box-v2' отклоняется (новый тест); сервер запрещает отключение
   E2EE (E2EE_CANNOT_DISABLE) и изменение payload с подменой body
   (E2EE_PLAINTEXT_FIELDS_FORBIDDEN); plaintext-fallback отсутствует
   (транспортные тесты).
6. **TOFU/device verification**: пин собеседника хранится в secure store
   (secrets['pins']); смена ключа сервером блокирует и отправку, и расшифровку
   (e2ee_identity_service.dart:212-215, :265-267) — молчаливой пере-закрепки
   нет; отпечатки SHA-256 сверяются вручную (e2ee_keys_screen.dart:123-131).
7. **Восстановление**: recovery-контейнер AES-256-GCM с AAD=[format, owner]
   (vault:20-23, :34-38) — бэкап чужого аккаунта не открывается (существующий
   e2ee_recovery_vault_test.dart:37); ключи поаккаунтно изолированы
   (e2ee_secret_store_test.dart:7); непреднамеренная повторная запись recovery
   даёт свежий nonce (тест :67).

**Опровергнуто (эксплуатация невозможна, причина/тест указаны):** подмена
ciphertext и nonce (AEAD), перенос пакетов между получателями/диалогами
(MAC+context), «читаемый» дубль сервером (context), downgrade версии (v2
rejected), чтение recovery-контейнера другого аккаунта (AAD).

**Подтверждённые ОГРАНИЧЕНИЯ протокола (документируются, не правятся):**

1. **Нет прямой секретности/ratchet**: один статический seed на аккаунт
   (identity_service:71-78); компрометация seed = чтение всей прошлой и
   будущей переписки + необнаружимая имперсонация (публичный ключ совпадает —
   пины собеседников не срабатывают). Признано в docs/E2EE_IMPLEMENTATION_RU.md.
2. **Нет привязки к устройству**: identity одна на аккаунт, «сессионных»
   ключей нет; любое устройство с seed неотличимо от владельца.
3. **Ротация/ревокация отсутствуют**: сервер IDENTITY_IMMUTABLE
   (e2ee_identity_schema.sql:39-42), клиент запрещает замену (:114-118) —
   компрометация необратима без админ-сброса; после сброса пины собеседников
   блокируют переписку до ручной пере-верификации, UI сброса пина нет.
4. **Обновление recovery-бэкапа невозможно** (RPC возвращает при совпадении
   ключа, e2ee_identity_schema.sql:39-42) — смена recovery-ключа оставляет
   старый envelope навсегда.
5. **Пин по устройству**: переустановка/новое устройство заново доверяет
   серверу на первом контакте (TOFU без memory).
6. Секреты (seed, recovery) существуют в Dart-куче как String без wiping —
   платформенное ограничение; SecureKey с dispose только для пар ключей
   (identity_service:76, 93, 140, 197, 251, 279-296).

## Безопасный план миграции (не применять в этой ветке)

- identity v2: prekeys/одноразовые ключи с атомарной выдачей (заготовка уже
  есть — libsignal 9.0.0 и e2ee_signal_runtime_test.dart, в lib/ не
  используется) либо MLS; device-ключи с серверным связыванием.
- Церемония ротации identity: окно перерегистрации + принудительная
  пере-верификация пинов у собеседников (новый UI-поток), уведомление о смене
  ключа в диалоге.
- RPC e2ee_update_backup(p_backup) при совпадении публичного ключа.
- Rollout: новые значения 'v' конверта (клиент уже отклоняет незнакомые —
  безопасный переход), серверный capability-флаг, отдельные флаги сборки.

## Тесты (локально, Windows, все прошли: 12)

- Новые (e2ee_box_invariants_test.dart): nonce uniqueness (1000), packet swap,
  nonce tamper + malformed packets, downgrade refusal.
- Существующие: e2ee_box_codec_test (контекст/чужой ключ/tamper),
  e2ee_recovery_vault_test (чужой аккаунт/чужой ключ/изменённый ciphertext,
  свежие nonce), e2ee_secret_store_test (изоляция/перезагрузка/гонки/неподтверждённая запись).

## Ограничения

- Локальные тесты libsodium на Windows; поведение OS CSPRNG/Keystore на
  Android в этом раунде не проверялось на устройстве (см. QA beta12 в
  docs/E2EE_IMPLEMENTATION_RU.md).
- Серверная сторона и RLS — вне раунда; заявления о применённых схемах не
  верифицировались.
-Nonce-уникальность подтверждена статистически на выборке, а не исчерпывающе.
