## Что теперь происходит в каждом сценарии

Модель результата: `GpxParseStatus { ok, truncatedPoints, oversized, invalidXml, noTrack }` + `totalTrackPoints` в `ParsedGpxTrack` (`lib/utils/gpx_utils.dart`). Маркер усечения ставится только когда кап 100 000 встретил СЛЕДУЮЩУЮ непрочитанную точку: ровно 100 000 точек — полный трек (`status = ok`). Внешний `break` по сегментам убран — он молча пропускал целые сегменты после капа; на результат это не влияет (внутренний `break` прекращает добавление), поэтому капы и экономия памяти сохранены, потоковый парсер не вводился.

| Сценарий | Раньше | Теперь |
|---|---|---|
| Файл ≤20 млн символов, ≤100 000 точек | «GPX-трек открыт на карте» | без изменений, `status = ok` |
| 100 001+ точек | «GPX-трек открыт на карте» над обрезанным треком | трек открывается + единственное сообщение «Трек открыт частично: показаны первые 100 000 из N точек, остальное пропущено» (без противоречащего «успешно открыт») |
| >20 млн символов | ложное «В GPX-файле не найден трек…» | «GPX-файл слишком большой (больше 20 млн символов). Трек не открыт.» Лимит задан длиной Dart-строки (UTF-16 символам), не байтами — формулировка соответствует реализации |
| Повреждённый XML | то же ложное сообщение | «GPX-файл повреждён: не удалось прочитать XML.» |
| Корректный GPX без trkpt/rtept | «не найден трек с двумя точками» | без изменений (`noTrack`) |
| Облачный заезд с обрезанным GPX | частичная геометрия могла уехать обратно в облако | `routePointsPartial = true` в `SavedRoute` (пишется в историю JSON), повторная выгрузка запрещена |

## Какие данные защищены от перезаписи

Путь перезаписи прослежен: облачная строка → `RidesService.rideFromRow` → `parseTrack` (обрезка) → история. Добавление отметки (`addRideMoment`) ставит `cloudSynced = false`, и `retryUnsynced` выгружал бы весь заезд через `GpxUtils.build(routePoints)` — обрезанный GPX перезаписал бы полный трек в `rides` по тому же id. Закрыто в двух точках:

1. `WorkoutHistoryRepository.addRideMoment` — для `routePointsPartial` явный отказ с текстом для пользователя (`HistoryRefusedException`, показывается в `ride_pulse_view.dart`); отметка не сохраняется вовсе.
2. `WorkoutHistoryRepository.retryUnsynced` — частичные заезды пропускаются без расхода лимита попыток (лог в debugPrint); их геометрия никогда не покидает устройство.

Исходный GPX-файл не изменяется (импорт только читает); сохранение истории/формат черновика/legacy-дедупликация/GPS/Signal/медиакэш не затронуты. `routePointsPartial` переживает запись/чтение истории и `withSyncState` (покрыто тестом round trip).

## Ограничения осознанно сохранённого поведения

- Капы не ослаблены: 100 000 точек и 20 млн символов — прежние значения.
- Облачная поездка с неполным треком по-прежнему отображается частично (без текстового предупреждения в карточке истории) — защита данных важнее сообщения; замена геометрии исключена.
- Импортированный частичный трек — это маршрут на карте, он не пишет историю поездок; файл-источник остаётся полным.
