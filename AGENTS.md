# PulsePath: краткие правила работы

По решению пользователя 02.11.2026 постоянный контекст ограничен этим файлом, PROJECT_STRUCTURE.md и docs/PROJECT_STATE_RU.md. Прежнее требование читать и дополнять журнал при каждой задаче отменено, в том числе в старых инструкциях навыка pulsepath-flutter. Документы из docs, журнал и архив открывать только для конкретного вопроса; старые планы не выполнять автоматически.

- Перед правкой проверить путь, git status, ветку и версию pubspec.yaml; изучить относящийся к задаче код. Сохранять чужие изменения, пользовательские данные и изоляцию аккаунтов.
- Делать изменения в рамках запроса; проверять затронутое поведение соразмерно задаче. Для UI учитывать реальные отступы и крупный шрифт. В отчёте разделять фактическую проверку, публикацию и проверку на телефоне.
- Не удалять файлы и код без прямого разрешения. Не очищать данные приложения и не понижать установленную версию.
- После изменений приложения завершать стабильный выпуск: GitHub Release + проверенный APK + каталог приложения + проверка серверной отправки push. Порядок: docs/GIT_AND_RELEASES_RU.md, читать при выпуске. Бета — для крупных экспериментов; UI Beta — отдельный пакет. Новые эксперименты требуют отдельного флага, UI_BETA не включает их все. Доступный подключённый телефон обновлять без очистки данных. Изменение только документации не требует APK.
- Не записывать всё подряд. Обновлять карту только при изменении структуры/функций, текущий статус — при смене задачи или существенного ограничения. Журнал необязателен; сохранять только решения, которые помогут продолжить работу. Не добавлять историю выпусков и полные логи в постоянный контекст.
