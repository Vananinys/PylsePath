# PulsePath: работа в любом новом чате

## Правила пользователя

1. Не удаляй код и файлы без разрешения пользователя.
2. Если подключён телефон, устанавливай на него обновлённую сборку приложения после изменений приложения. Не очищай данные и не удаляй приложение для установки; при неоднозначном выборе устройства уточни цель. Изменение документации/навыка не требует сборки APK.
3. Используй навык `pulsepath-flutter` для разработки, анализа, планирования и продолжения работы по PulsePath.

## Восстановление контекста перед работой

- Сначала прочитай `docs/PROJECT_STATE_RU.md` полностью, затем последние записи `docs/AI_WORK_NOTES.md`. Для истории конкретного модуля ищи по журналу, не перечитывай весь архив без необходимости.
- Проверь `git status --short`, текущую ветку и последние коммиты. Сверь версию в `pubspec.yaml`. Сохраняй чужие незакоммиченные изменения.
- Используй `PROJECT_STRUCTURE.md` как указатель к модулям; его старые счётчики строк не являются текущей картой кода. Прочитай связанные с задачей исходники и документы из индекса сводки.
- Различай: реализацию в коде, успешный тест, опубликованный APK, подтверждённую серверную отправку push и физическую проверку на телефоне. Это разные факты.
- При расхождениях приоритет имеют прямые указания пользователя и актуальный код/проверенное внешнее состояние. Дата сводки не делает сведения вечными. Не объявляй задачу завершённой по старому отчёту.

## Продолжение и завершение

- Следуй `docs/GIT_AND_RELEASES_RU.md`: обычные улучшения и исправления выпускаются стабильно; бета — для экспериментальных изменений. При выпуске нужны GitHub Release, проверенный APK, каталог приложения и проверка отправки уведомления.
- После содержательной работы добавь в `docs/AI_WORK_NOTES.md` краткую запись: решение, затронутые модули, фактические проверки, публикация/установка и ограничения. Старые записи сохраняй.
- Если изменились функции, ограничения, текущий релиз или порядок продолжения, актуализируй `docs/PROJECT_STATE_RU.md`. Полные логи держи в `audit/`, а секреты, ключи и личные данные не записывай в контекст проекта.
- Перед завершением явно оставь следующий шаг и блокирующие зависимости. Запрос «продолжи» связывай с актуальной задачей из переписки/журнала, не начинай проект заново и не выполняй старый план автоматически без проверки его актуальности.
